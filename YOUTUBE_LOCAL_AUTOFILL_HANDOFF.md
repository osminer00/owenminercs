# YouTube Local Autofill Handoff (No API Yet)

## Goal

Automatically fill Social Cloud cards with your YouTube Shorts and YouTube Videos using a **local build-time script**, not `/api/social-feed` yet.

This should remove manual card editing in `Socials/scripts/social-cloud.js` while keeping everything local/static for now.

---

## Scope For Next Agent

1. Build a local ingestion script that pulls channel uploads and shorts metadata.
2. Rank content in curated order (high views, high likes, recent posts prioritized).
3. Output local JSON files committed to the repo.
4. Update social cloud frontend to read from these local JSON files first.
5. Keep existing card interactions unchanged (drag/pin/resize/rotate).

---

## Hard Constraints

- Do **not** use backend API endpoints for this task.
- Do **not** require YouTube Data API keys for this task.
- Do **not** break current card interaction UX.
- Do **not** include livestream content yet.

---

## Current Context

- Social page renderer lives in `Socials/scripts/social-cloud.js`.
- There is currently logic for fetching `/api/social-feed` and manual fallback.
- Manual content currently mixes uploads, shorts, and older livestream-oriented entries.
- We want a local content source generated by script and checked into git.

---

## Desired Local Data Model

Create these files:

- `Socials/data/youtube-shorts.json`
- `Socials/data/youtube-videos.json`

Each file should contain an array of normalized items:

```json
[
  {
    "platform": "youtube",
    "contentType": "short",
    "title": "Video title",
    "url": "https://www.youtube.com/shorts/<id>",
    "thumbnail": "https://i.ytimg.com/vi/<id>/hqdefault.jpg",
    "caption": "description",
    "publishedAt": "2026-01-01T00:00:00.000Z",
    "viewCount": 12345,
    "likeCount": 678
  }
]
```

`contentType` should be:

- `short` for shorts
- `video` for standard uploads

---

## Ingestion Strategy (No API Key)

Use `yt-dlp` from local script (Node `child_process`) to read channel data:

- channel URL: `https://www.youtube.com/@OwenMinerCS`
- parse metadata from playlist/entries
- capture at minimum:
  - id
  - title
  - description
  - upload date / timestamp
  - duration
  - view_count
  - like_count (if present)
  - live status flags

Recommended script path:

- `scripts/sync-youtube-local-feed.mjs`

Recommended npm script:

- `"sync:youtube-local": "node scripts/sync-youtube-local-feed.mjs"`

If `like_count` is missing from some entries, treat it as `0`.

---

## Filtering Rules

Exclude all livestream-like content:

- known live/upcoming flags from metadata
- titles/descriptions containing livestream markers
- URLs containing `/live/`

Classify as short vs video:

- short if duration <= 70 seconds, or URL/title indicates shorts
- otherwise video

---

## Curation / Ranking Rules

Sort within each list using a weighted score:

- high views (strong weight)
- high likes (strong weight)
- recency boost (moderate weight)

Then:

- `youtube-shorts.json` should include all filtered shorts, sorted best -> worst by score
- `youtube-videos.json` should include all filtered standard videos, sorted best -> worst by score

Optional cap (if rendering performance needs it):

- keep top 150 shorts
- keep top 100 videos

---

## Frontend Integration Requirements

Update `Socials/scripts/social-cloud.js`:

1. Load local JSON files (shorts + videos) via `fetch()` from `Socials/data/`.
2. If local JSON exists and has items, use it as the source of truth.
3. Keep existing manual array only as final emergency fallback.
4. Preserve per-card aspect ratio behavior:
   - shorts -> `9:16`
   - videos -> `16:9`

Important:

- For now, prefer shorts-only rendering by default on social cloud.
- Keep videos available in the loaded catalog for future toggles.

---

## Validation Checklist

- `npm run sync:youtube-local` generates both JSON files.
- Social page renders from local JSON (no API dependency required).
- No livestream cards appear.
- Shorts render with `9:16` card ratio.
- Standard videos render with `16:9` card ratio.
- No duplicate card entries by YouTube video id.
