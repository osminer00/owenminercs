Dev stack

This site is static HTML, CSS, and a little browser JavaScript. Nothing here is a secret recipe — it is the honest split of tools used to ship fixes and content without turning the repo into a second job.

Editor

Cursor

Primary IDE + agent workspace

Cursor is where almost everything lands: multi-file edits, refactors, navigating this repo, and running the integrated agent against real paths. It is the default for day-to-day changes when I want fast feedback and tight loops with the codebase open beside the chat.

 
CLI / IDE

Codex (OpenAI)

Terminal and alternate passes

Codex-style workflows get used when a terminal-first pass helps: batch edits, quick scaffolding, or a second opinion after Cursor. Handy when the task is narrow and I already know exactly what to verify afterward.

 
Assistant

Claude

Long explanations & careful wording

Claude is the choice for bigger reasoning chunks: nuanced copy, accessibility wording, structuring a page, or walking trade-offs before touching files. Not tied to one vendor UI — whatever Claude-shaped surface is available for that session.

 
Experiment

Antigravity

Parallel tries & exploratory UI

Antigravity comes out when I want an isolated or experimental pass — mockups, alternate layouts, or ideas that might not ship. Keeps risky “what if” work off the main editing lane until it is worth merging back.

 
Local

Ollama

Offline drafts on the RTX box

Ollama runs locally for first drafts of repetitive HTML/CSS text, list transforms, and bulk summaries where I can verify output immediately. If it is slow or off-topic, I switch back to a hosted model without guilt — local is for savings and privacy-tolerant grunt work, not gatekeeping quality.

 

No API keys or account identifiers belong on a public page — store those in your own password manager and environment, not in git.
